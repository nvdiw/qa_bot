# QABot - ربات پاسخ‌دهی خودکار

ربات تلگرامی برای پاسخ خودکار از روی فایل CSV، با پنل نقش‌بندی‌شده `admin` و `owner`.

## ویژگی‌ها

- جستجوی هوشمند (Fuzzy) روی سوالات CSV
- صف سوالات بی‌پاسخ (تیکت)
- پاسخ ادمین با Reply روی پیام تیکت
- افزودن/حذف سوال و جواب از داخل ربات
- نقش‌بندی `admin` و `owner`
- ذخیره پایدار نقش‌ها در `data/access_control.json`
- منوهای فارسی برای کاربری ساده

## نقش‌ها

### Admin
- دریافت خودکار سوالات بی‌پاسخ
- پاسخ به تیکت‌ها با Reply
- مدیریت محتوا:
  - افزودن سوال
  - حذف سوال
  - لیست سوال‌وجواب
  - آمار
  - بارگذاری مجدد CSV

### Owner
- تمام دسترسی‌های Admin را دارد
- مدیریت ادمین‌ها:
  - نمایش لیست ادمین‌ها (همراه `chat_id/user_id` و `username`)
  - افزودن ادمین با `chat_id/user_id`
  - حذف ادمین با `chat_id/user_id`
- نکته مهم:
  - سوالات بی‌پاسخ **به‌صورت خودکار فقط برای Adminها** ارسال می‌شود.
  - Owner برای پاسخ دادن باید از منوی «سوالات بی‌پاسخ» وارد شود و روی همان پیام تیکت Reply بزند.

## نصب

```bash
pip install -r requirements.txt
```

## تنظیمات `.env`

حداقل تنظیمات پیشنهادی:

```ini
BOT_TOKEN=YOUR_BOT_TOKEN

# سازگاری با نسخه قدیمی (اختیاری)
ADMIN_ID=123456789

# ادمین‌ها (بدون owner) - جداشده با کاما
ADMIN_IDS=123456789,987654321

# owner ها - جداشده با کاما
OWNER_IDS=555555555

# کلید دستور امن /secureid
ADMIN_DISCOVERY_KEY=YOUR_SECRET_KEY
```

نکته:
- اگر `OWNER_IDS` خالی باشد، سیستم برای جلوگیری از قفل‌شدن دسترسی، از adminهای اولیه به‌عنوان owner اولیه استفاده می‌کند.

## اجرای ربات

```bash
python main.py
```

## دستورات

### عمومی
- `/start` شروع
- `/help` راهنما

### Admin
- `/admin` منوی ادمین
- `/stats` آمار
- `/list` لیست سوال‌وجواب
- `/pending` سوالات بی‌پاسخ
- `/reload` بارگذاری مجدد داده CSV

### Owner
- `/owner` منوی owner

### ابزار کمکی
- `/secureid <ADMIN_DISCOVERY_KEY>` نمایش `chat_id` و `user_id` در چت خصوصی

## منوهای فارسی

بخش زیادی از عملیات روزمره از طریق دکمه‌های فارسی انجام می‌شود (بدون نیاز به تایپ دستی دستورها)، مخصوصاً برای Owner.

## ساختار داده

- `data/qa_data.csv`: بانک سوال/جواب
- `data/bot_stats.json`: آمار ربات
- `data/access_control.json`: نقش‌های `admin` و `owner` (پایدار بعد از ری‌استارت)

## جریان پاسخ‌دهی

1. کاربر سوال می‌پرسد.
2. اگر جواب در CSV پیدا شود، همان لحظه ارسال می‌شود.
3. اگر جواب پیدا نشود:
   - تیکت ساخته می‌شود.
   - فقط برای Adminها ارسال می‌شود.
4. Admin با Reply پاسخ می‌دهد:
   - پاسخ برای کاربر ارسال می‌شود.
   - سوال/جواب در CSV ثبت می‌شود.
   - تیکت بسته می‌شود.

## عیب‌یابی سریع

- خطای `BOT_TOKEN`:
  - مقدار `BOT_TOKEN` را در `.env` بررسی کنید.
- نبود admin/owner فعال:
  - `ADMIN_IDS` یا `OWNER_IDS` را تنظیم کنید.
- سوالات بی‌پاسخ برای Owner ارسال نمی‌شود:
  - رفتار سیستم عمدی است؛ Owner از منوی «سوالات بی‌پاسخ» وارد می‌شود.

## نکات امنیتی

- فایل `.env` را در مخزن عمومی قرار ندهید.
- `ADMIN_DISCOVERY_KEY` را محرمانه نگه دارید.
- دسترسی owner را محدود به افراد قابل اعتماد نگه دارید.
